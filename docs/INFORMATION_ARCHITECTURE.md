# Architecture de l'information

Cette architecture décrit la direction du site. Toutes les sections ne doivent pas être développées dès la V1.

## Principe d'expérience

La profondeur de l'architecture ne doit pas devenir une charge cognitive pour le visiteur. **Le système peut être complexe ; l'entrée doit rester simple.**

Test transversal : un enfant d'environ 11 ans ou une personne âgée peu familière de la callisthénie doit comprendre rapidement ce qu'elle peut faire sur Calis.

## Navigation visible V1 actuelle

La navigation principale est volontairement courte :

- **Je débute** → `/commencer` ;
- **Choisir un objectif** → section objectifs de l'accueil ;
- **Tout explorer** → `/bibliotheque`.

L'accueil part de formulations humaines : « faire ma première traction », « faire ma première pompe », « tenir sur les mains », « réussir un muscle-up », « renforcer mes jambes », « bouger plus facilement ».

La page `/commencer` part de situations observables : « je n'arrive pas encore à faire une pompe », « je n'arrive pas encore à faire une traction », « je me sens raide », etc.

Ne pas exposer les termes internes `hub`, `cluster`, `capability`, `ProgressionEdge` ou « régression » comme prérequis de navigation. Ils servent le système et peuvent être expliqués seulement lorsqu'ils deviennent utiles.

## Architecture profonde cible

### Apprendre
- Commencer de zéro
- Fondamentaux
- Exercices
- Figures
- Mobilité
- Récupération

### Progresser
- Parcours par objectif
- Progressions
- Programmes
- Tests de niveau
- Outils
- Journal de progression (futur)

### Comprendre
- Biomécanique
- Anatomie fonctionnelle
- Force et hypertrophie
- Volume, intensité et récupération
- Sensations et contrôle du mouvement
- Questions fréquentes approfondies

### S'équiper
- Guides d'achat
- Comparatifs
- Tests
- Catégories de matériel
- Boutique

### Pratiquer (futur)
- Parcs
- Clubs
- Coachs
- Associations
- Événements
- Compétitions

Ces branches structurent le produit et le futur maillage ; elles n'ont pas besoin d'être toutes présentes simultanément dans le menu principal.

## Capacités

La bibliothèque et le graphe peuvent être organisés par capacité :

- pousser ;
- tirer ;
- tenir ;
- s'équilibrer ;
- se mouvoir ;
- devenir plus fort ;
- jambes.

La capacité est une structure pédagogique après orientation, pas forcément le premier vocabulaire montré au débutant.

## Hubs actuels et futurs

### Actuels V1
- Tractions
- Pompes
- Dips
- Handstand
- Muscle-up

### Vagues suivantes
- Front lever
- Back lever
- Planche
- Human flag
- L-sit

Un hub n'est pas un simple article. Il rassemble le désir/problème associé, les prérequis, la technique, les erreurs, les progressions, les régressions, les diagnostics, les programmes/questions connexes et le matériel réellement pertinent.

## Modèle d'une fiche d'apprentissage

1. résultat recherché / problème humain ;
2. première réponse utile ;
3. où se situe la personne ;
4. première action réalisable ;
5. technique ;
6. ce que l'on doit ressentir ;
7. signaux à ne pas ignorer ;
8. erreurs fréquentes ;
9. simplification/régression ;
10. progression ;
11. critère pour passer à l'étape suivante ;
12. variantes ;
13. matériel nécessaire, facultatif ou inutile ;
14. ce que cela débloque ensuite ;
15. ressources liées ;
16. sources et relecteurs éventuels.

## Maillage

La logique interne cible est :

`désir / problème → diagnostic → action → progression → capacité suivante → programme / équipement pertinent éventuel`

Le maillage doit d'abord aider le lecteur ; sa valeur SEO vient de cette structure cohérente.

## Règle d'évolution

Simplifier l'interface ne signifie pas supprimer la profondeur existante. On conserve le contenu, les hubs, les filtres et le graphe utiles ; on améliore l'ordre, les mots et les portes d'entrée.
